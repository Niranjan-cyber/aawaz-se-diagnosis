### B03 — Speak and get diagnosed
- **Status:** todo
- **Goal:** A student records (or plays the sample clip of) a spoken Hindi explanation and sees the Saaras transcript plus the named misconception, with the evidence phrase highlighted.
- **Why now:** This is the riskiest unknown and the winning feature: if Saaras plus 105B JSON classification is unreliable, we want the fallback with time left.
- **Slice:** UC UC-01 · Screens S-01, S-02 · Components backend, frontend, Saaras, Sarvam-105B
- **In scope:** Browser MediaRecorder with a Record/Stop UI; 'Play sample' button using a Bulbul-generated Hindi clip saved to public/samples/; POST /diagnose (audio) calls Saaras v3 with hi-IN, then 105B with a fixed label list; Label set: M1 bigger denominator means bigger fraction, M2 add numerators and denominators, M3 whole-number thinking, M4 none; Transcript card plus a misconception card with a confidence chip
- **Out of scope:** Re-teaching; Drills
- **Skills (in order):** —
- **Acceptance:**
  - [ ] The sample clip returns transcript text and misconception M1 within 10 s
  - [ ] A silent or too-short recording shows 'we couldn't hear you, try again', never a diagnosis
  - [ ] If the 105B output is not valid JSON, the app shows 'unsure' with a Retry, not a made-up label
  - [ ] The API key never appears in frontend code or network responses
- **States:** S-01: empty, running, failed; S-02: success, failed
- **Tests:** unit: classifier JSON parser handles valid, fenced-in-markdown and garbage outputs; unit: unknown misconception ids map to M4; integration: POST /diagnose with the sample clip returns 200 and a transcript; with an empty file returns 422
- **Browser check:**
  1. Open <FRONTEND_URL>/speak, click Play sample, and take screenshot b03-success.png of the diagnosis
  2. Submit an empty recording and take screenshot b03-failed.png
  3. Reload and confirm the page returns to the idle state: b03-reload.png
- **Done when (on the public URL):**
  1. Open <FRONTEND_URL>/speak, click Play sample, and see the transcript and M1 within 10 s with no sample badge
  2. The browser check passes and its screenshots are reviewed
- **Fallback:** If the live mic or Saaras fails on stage, DIAGNOSE_MODE=fixture returns the recorded sample transcript and diagnosis.
- **Deploys:** frontend, backend · **After:** B02 · **Est.:** 0.12 h
- **Prompt:** `prompts/B03-speak-and-get-diagnosed.md`
- **Notes:** Parameter names differ between SDK docs (language_code and target_language_code, saaras:v3). Check against the installed sarvamai version. Creative touch: highlight the exact spoken phrase that revealed the misconception.

### B04 — Re-teach in three modalities
- **Status:** todo
- **Goal:** After a diagnosis, the student picks Story, Number line or Real-life analogy and sees a Hindi re-teach for that misconception, which they can hear through Bulbul.
- **Why now:** Second half of the core loop (diagnose, then fix), and it shows off Bulbul.
- **Slice:** UC UC-02 · Screens S-02 · Components backend, frontend, Sarvam-105B, Bulbul
- **In scope:** POST /reteach {misconception_id, modality} generates Hindi text with 105B, cached per pair in SQLite; POST /tts calls Bulbul and returns base64 audio; Number line is a React SVG component that plots the two fractions from the diagnosis; Tabs for the 3 modalities and a Listen button; Echo-back: Bulbul first repeats the student's reasoning kindly ('Tumne socha ki...')
- **Out of scope:** Drills; Streaming audio
- **Skills (in order):** —
- **Acceptance:**
  - [ ] Each of the 3 modalities renders Hindi content for M1 within 8 s, and the second view is instant from cache
  - [ ] The number line shows 1/3 and 1/2 at the correct positions
  - [ ] If Bulbul fails, the text still shows and Listen shows 'audio unavailable, retry'
  - [ ] Content is never blank: a failed generation shows an error, not an empty card
- **States:** S-02: loading, success, failed
- **Tests:** unit: the cache returns the stored text on the second call without calling the model; unit: number line position maths (a/b to x coordinate); integration: POST /tts returns base64 audio that decodes to a non-empty WAV
- **Browser check:**
  1. From the diagnosed state, click each tab and take screenshots b04-story.png, b04-numberline.png, b04-analogy.png
  2. Force a Bulbul failure and take screenshot b04-audio-failed.png
- **Done when (on the public URL):**
  1. Open <FRONTEND_URL>/speak, diagnose the sample, open all 3 tabs, and play Listen
  2. The browser check passes and its screenshots are reviewed
- **Fallback:** RETEACH_MODE=fixture serves hand-written Hindi text for M1, and audio is pre-generated.
- **Deploys:** frontend, backend · **After:** B03 · **Est.:** 0.1 h
- **Prompt:** `prompts/B04-re-teach-in-three-modalities.md`
- **Notes:** Keep prompts under about 60 words to save tokens.

### B05 — Spoken drill and mastery update 🏁 prototype exit
- **Status:** todo
- **Goal:** The student hears a Bulbul-spoken drill, answers aloud, gets feedback, and sees the skill's mastery graph move on the Mastery screen.
- **Why now:** Closes the loop (diagnose, teach, practise, track) and delivers the prototype exit.
- **Slice:** UC UC-03 · Screens S-03, S-04 · Components backend, frontend, Saaras, Sarvam-105B, Bulbul
- **In scope:** POST /drill generates 3 targeted questions for the skill, with Bulbul audio each; POST /answer: Saaras transcribes, a simple check or 105B marks it, and the mastery score updates (+0.15 right, -0.05 wrong); Mastery 'constellation' SVG: skills as nodes, brightness equals score, animating on change; Tap-to-answer fallback buttons for noisy rooms
- **Out of scope:** Auth, multiple students, adaptive difficulty
- **Skills (in order):** —
- **Acceptance:**
  - [ ] A correct spoken answer raises the targeted skill's score and the graph visibly updates
  - [ ] An unintelligible answer is not marked wrong: it shows 'say that again' and the score is unchanged
  - [ ] The mastery score survives a page reload, because it is read from the API
  - [ ] If drill generation fails, the screen shows an error with Retry and the mastery screen still loads
- **States:** S-03: loading, running, success, failed; S-04: success, failed
- **Tests:** unit: the answer normaliser maps 'ek tihai' and '1/3' to the same value; unit: the mastery update rule clamps to 0..1; integration: POST /answer with a correct clip raises mastery; with an empty file returns 422 and leaves mastery unchanged

  3. Force an API failure on the drill and take b05-failed.png
- **Done when (on the public URL):**
  1. On <FRONTEND_URL>, walk the whole golden path in under 90 s with no sample badges
  2. The mastery graph for fraction comparison changes after a correct answer and still shows the change after a reload
  3. The browser check passes and its screenshots are reviewed
- **Fallback:** Tap-to-answer buttons count as the answer if the mic or Saaras is flaky.
- **Deploys:** frontend, backend · **After:** B04 · **Est.:** 0.12 h
- **Prompt:** `prompts/B05-spoken-drill-and-mastery-update.md`
